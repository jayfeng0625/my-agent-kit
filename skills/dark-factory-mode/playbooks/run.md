### Run

**You own the queue. Claim, delegate, verify, park.**

1. **Start gate.** In one message, confirm the queue (a tracker query or a ticket list), the base branch, the landing grant (`none`, the default, or `prs`; see **Gates**), and that the runner's tracker commands and the lanes' commands (tests, builds, local services) run without permission prompts, through auto mode or an allowlist. Check that every tracker status in **Ticket states** exists, and under `prs` that `gh auth status` passes and a push runs without a prompt. Pipe each queued ticket's body to `node ~/.claude/skills/dark-factory-mode/scripts/check-plan.mjs --ticket -`; a ticket that fails parks as `needs-info` with the script's output, since its Verify blocks are what the verdict checks. The Plan playbook writes tickets that pass. A missing `ScheduleWakeup` stops the run here; a missing `PushNotification` goes in the digest and the run goes on. Then create the run directory and start the trail. A runner that holds a run id, from the user or from its run directory after a compaction, skips this step.
2. **Resume.** List In Progress and Ready For Human Review tickets whose `claimed` comment names this run's id. Carry each In Progress ticket forward from the stage its latest comment names, after a `stat -L` per mode-core's Stall check on the lane output file its attempt comment records: a live lane is not respawned, and an attempt comment with no output file means no lane started. A Verified ticket stays Verified.
3. **Frontier.** Take every queued ticket whose blockers are Done or Verified in this run, and park the ones the Dependent tickets trigger parks. Order by blocking edges, then tracker order.
4. **Claim.** Post a `claimed` comment naming the branch `df/<ticket-id>` and the run directory, then move the ticket to In Progress. A `df/<ticket-id>` branch already on the remote parks the ticket.
5. **Lane.** Post the `attempt <n>/3` comment, spawn the ticket's lane per **Roles and context**, then record the lane's output file in a comment. Its scope names the ticket, the base ref (the blocker's branch, else the base branch), the worktree path, the defaults this run has recorded, and the Any ask or pause trigger and the Gates list verbatim. Every live agent counts against mode-core's Fan-out limit of 5, lane reviewers and verifiers included, so start a lane only when its reviewer fits too.
6. **Heartbeat.** Lane notifications wake the runner. A fallback `ScheduleWakeup` of 20 to 30 minutes covers a hung lane, and each wake runs mode-core's Stall check. A stalled lane counts toward the ticket's 3 lanes, and a ticket whose lanes stall twice parks.
7. **Review and verdict.** When a lane hands back, spawn its reviewer per **Roles and context** on the lane's head. Findings it tags `blocking` go to a fresh lane as in step 8, and that head gets a fresh review, up to 3 rounds. A third round that still has `blocking` findings parks the ticket with them. After a clean round, run the verification swarm per **Roles and context** on that head, with the same base ref in each lane's scope, as a rolling window under the Fan-out limit. Post the verdict with its head SHA. An INCONCLUSIVE lane gets one fresh lane; a second INCONCLUSIVE parks the ticket with the evidence. A full swarm runs once per ticket, at the first head to pass review, and again only for a head that adds behavior or a large diff. A minor fix, a rebase or a CI fix gets one verifier at the new head that reruns the gates lane and lane 1 and reads the change, and a wording-only change gets none; the other lanes' results stand when `git patch-id` matches the swarm's head, or differs only in tests, docs or lint config.
8. **Retry or park.** A FAIL or `blocking` review findings go to a fresh lane with consolidated scope: the brief, the verdict's findings and the branch, in the same worktree path. A ticket gets 3 lanes in total, then parks with the last verdict. A lane that parked on a question parks its ticket at once.
9. **Verified.** The lane writes its PR body with the **pr** skill into an uncommitted file in its worktree, named in its report. Copy it to `pr/<ticket>.md`, since the runner never reads the diff. Under grant `none`, move the ticket to Ready For Human Review with a `verified` comment. Under `prs`, push `df/<ticket-id>`, open a ready PR from `pr/<ticket>.md` against the base ref, and post a `pr-open` comment with its link; then babysit it on step 6's wakes until CI is green on the verified head:
   - a failing check in code the ticket touches goes to a fresh lane as in step 8, and its new head gets step 7's verdict before the push;
   - a check that also fails on the base ref is not the ticket's: rerun it once, and if it still fails, name it in the `verified` comment and the digest;
   - a bot review comment goes to the next reviewer round as a finding to verify; a person's comment waits for the user and goes in the digest.
   Once every check the ticket owns is green on a head with a PASS, move the ticket to Ready For Human Review with a `verified` comment naming the PR.
10. **Loop.** Return to step 3 until the frontier is empty and no lane is running. Then park every ticket still queued, naming the blocker or cycle that held it.
11. **Digest.** Under grant `none`, regenerate `land.sh` from the Verified tickets in stack order; under `prs`, list each PR in stack order in its place. Then write `digest.md` with the trail review's Attention section, send a `PushNotification`, and meet every item in **Verify**.

A tracker write that still fails after 3 retries with backoff stops new lanes. Running lanes finish, and the digest leads with the outage.

**Reply:** the digest, which leads with what the user must do and in what order:

- the land command (`bash ~/.dark-factory/<repo>/<run-id>/land.sh`) and the stack order, or under `prs` the PR links in merge order;
- each Parked ticket, with the decision or input it waits on;
- each Verified ticket, with its branch, head SHA, diff stat, each swarm lane's one-line result, its review-gate screenshots, the defaults the lane chose, and the models (lane and swarm);
- the follow-ups parked from findings that did not block;
- the run's cost in lanes, retries and wall time, and any missing tool.
